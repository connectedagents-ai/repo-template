# Morning brief

Personal content (identity, principles, life areas, named matters) lives only in the principal's private operating file
(a Claude Project instruction or private Drive doc). Read it first; this skill holds the structure only.

## Steps
1. Read the private operating file: priority tiers, operating principles, current 90-day results.
2. Pull today's calendar, open tasks (Todoist for personal/business, Linear for dev work) and unanswered threads that need the principal.
3. Rank every item by tier: **1 existential** (legal/financial deadlines) → **2 revenue** → **3 strategic** → **4 operational** → **5 personal**.
   A tier-1 item always comes first, whatever else is due.
4. Write the brief in this shape, nothing more:

```
CRITICAL FIRST:      tier-1 items with their deadline and the next concrete action
TODAY'S CALENDAR:    events, each with its purpose and desired outcome (flag any without one)
3 RESULT BLOCKS:     Result: why it matters: 3 actions   (×3, from tiers 2–3)
DECIDE TODAY:        items 30+ days overdue, each with a proposal: do / schedule / delegate / drop
ONE QUESTION:        a single reflection question tied to this week's main result
```

## Rules
- Every item names its source (task ID, event, thread). Mark anything unverified as UNVERIFIED.
- Read-only: propose changes to tasks and calendar; make them only when the principal says so.
- No privileged legal content goes into a general-purpose tool or memory.
